# 残差候选的证明指标清单（书籍框架 → 可测量化）

问题：若访存模型不能覆盖 8× 下 guest 提升，如何用指标逐项证明/排除各候选。
事件可用性已在 188 实查（perf list）。SMT 拓扑已确认：**相邻 CPU 对 (0-1, 8-9…) 为同物理核**，每 CCL 16 CPU = 8 物理核×2 线程。

---

## ① 指令数增长（重试/自旋/内核路径）

| 指标 | 采集 | 证明判定 | 状态 |
|---|---|---|---|
| inst 8x/1x 每 episode 比值 | percpu.csv（已有） | >1.05 → 成立，`Δinst × 基础CPI` 直接入账 | **零成本，已在管线** |
| guest_user vs guest_sys 拆分 | GSTAT（已有） | guest_sys 涨 → 内核路径增长定性 | 已有 |

## ② 共享行一致性膨胀（Levinthal：共享行命中 +62~87%）

**架构修正（重要）**：本场景 guest 页 = 每 VM 私有物理页（guest page cache 在 guest RAM，无 KSM 去重）→ "56 拷贝共享同一物理行"**不成立**，真正共享行仅限宿主内核结构/ublk 缓冲/层页 → **该候选预期份额小，降权**。

| 指标 | 采集 | 证明判定 |
|---|---|---|
| `bus_access` 率（一致流量核上代理） | percpu perf 加 1 事件（核级事件，预期与 cycles 一样含 guest） | bus_access/inst 8× 显著涨 → 有流量；平 → 排除 |
| 共享 vs 私有探针（定制） | 两进程追**同一物理环**（shared/forwarded 态）对比各追私有环 | 命中差价 >20ns 且份额可观 → 成立；否则排除 |

## ③ TLB / 页表遍历（书籍 §MMU）

| 指标 | 采集 | 证明判定 |
|---|---|---|
| **`dtlb_walk + itlb_walk` 周期**（页走直接成本！） | percpu perf 加 2 事件（已确认在位） | 增量周期/频率 = 秒数，直接对比残差 |
| `l1d_tlb_refill`、`dTLB-load-misses/loads` | 同上（refill 率） | 率 8×/1× >1.5 → TLB 侧显著 |
| `l1i_cache_refill`（i-cache 顺带） | 同上 | 同上 |

换算：每次 refill 页走 2-4 级 × 每级命中 L3/DRAM 的时延（~30-140ns）。

## ④ SMT sibling 争用（书籍 §6.3.6：低 IPC 负载惩罚小 → 预期 <10-15%）

| 指标 | 采集 | 证明判定 |
|---|---|---|
| **sibling 冲突率**（免新采！） | **percpu.csv 的 cycles 按 CPU 拆**（已有）→ victim 所在 CCL 内配对 (0,1)(2,3)…两线程同时 busy 的概率 | 1× vs 8× 冲突率对比 × 书中 SMT 性能曲线 → 估算贡献 |
| **SMT 隔离臂（决定性对照）** | E2 框架加一臂：taskset 把 victim 钉到孤立物理核（sibling 禁占）vs 正常共享 | 两臂 guest 差 = SMT 贡献，直接证明 |

## percpu perf 事件取舍（PMU 每核 6 计数器约束）

现有 4 个（cycles/instructions/LLC-loads/LLC-load-misses）+ 建议加 3 个：

```
保留: cycles, instructions, LLC-load-misses（MPKI 必需；LLC-loads 可让 miss% 由 dTLB 侧近似替代——或接受轻度复用）
新增: dtlb_walk, l1i_cache_refill, stalled-cycles-backend（7 事件 → 轻度多路复用，1s 间隔下统计可接受）
可选: bus_access（若复用严重则替换 stalled-cycles-backend）
```

## 检验顺序（成本升序）

1. inst 比对（已有，先查）
2. dtlb_walk / l1i_refill / stalled-backend 三事件（加入 8× 重发）
3. sibling 冲突率（从现有 percpu.csv 直接算）
4. SMT 隔离臂 + 共享探针（定制实验，按需）

预期：①③⑤ 组合应能覆盖大部分残差；②④ 按书的预测贡献有限。
