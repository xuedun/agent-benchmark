# 书籍视角：guest 残差的候选分析（性能之巅 §6 应用）

问题：若访存时延模型（`ΔT_访存 ≈ inst×[ΔMPKI×(DRAM−L3) + MPKI×ΔDRAM]/1000`）不能完全覆盖 8× 下 guest 的提升，残差可能来自哪里？

依据：《Systems Performance》第 6 章（CPU）、第 7 章（内存）、第 2 章（方法论），按 skill 输出模板组织。

---

## 一、方法论推理（性能方程，第 2 章）

`guest = 指令数 × CPI / 频率`。频率实测恒定（2.6GHz）→ 残差只能落在：

1. **指令数变化**（工作负载行为变了——重试/自旋/内核路径）
2. **CPI 的非访存停顿**（访存模型只覆盖了 miss 部分）

偏差分析方法（书 §2）：先量化基线差异（inst 1× vs 8× 已采），再逐项归因 CPI 栈。

## 二、分析框架（CPI 栈分解，书 §6.3.7）

```
CPI = 基础执行
    + 访存停顿（命中 + miss）          ← 当前模型覆盖
    + TLB 未命中停顿（页表遍历）       ← 候选③
    + 分支预测失败                     ← 与负载无关，预计≈0
    + 执行资源争用（SMT sibling）      ← 候选②
    + 一致性流量停顿（共享行）         ← 候选④（书中 Levinthal 数据）
```

## 三、书中关键信息（本章新引入两个此前未充分考虑的机制）

### 1. 缓存一致性抬高 LLC **命中**时延（§6 "缓存一致性"，引 Levinthal 09）

> "LLC 命中，缓存行未共享：约 40 CPU 周期；LLC 命中，缓存行与另一个核共享：约 65 周期；被另一个核修改：约 75 周期。"

**共享/修改行的 LLC 命中要多付 60-85% 延迟**。应用到我们的场景：
- 56 份拷贝**共享同一模板的源码页**（overlaybd 共享层 + 宿主 page cache，同一物理行映射到多个 guest）
- 1× 时少量核共享这些行；8× 齐射时**跨核共享密度大幅上升**（多 VM 同刻读同一批模板页）→ 命中路径变贵
- **修正此前假设**："L3 命中时延为常数"只对私有行成立；**共享行（模板页、libc 等公共代码）的命中时延负载相关**——这部分残差不进 MPKI（它是命中不是 miss）却进 CPI
- 检验：挑一个"共享行敏感"的探针变体（访问固定同一物理页集合的多进程）或对比私有/共享页构建的时延差

### 2. SMT 的负载依赖效应（§6.3.6）

> "每个硬件线程的性能与单独的 CPU 核不同，并且取决于负载。停滞周期密集（低 IPC）的负载比运算周期密集的负载往往有更好的性能，这是因为停滞周期降低了对核的争用。"

- 950 每 CCL = 8 核×2 线程：1× 时 vCPU 基本独占物理核，8× 时 sibling 被占 → 执行单元/L1/L2 分摊
- 书的洞察反直觉：我们的负载**恰好是低 IPC（访存停顿密集）型** → SMT 惩罚比计算型负载小——所以 SMT 是候选但预期贡献有限
- 检验：IPC 降幅与 MPKI 增幅不相称时查 vCPU-sibling 并发

### 3. MMU/TLB 页表遍历（§6 MMU）

> "MMU 通过芯片上的 TLB 缓存地址转换。主存（DRAM）里的转换表处理 TLB 未命中……较新的处理器可以通过硬件响应 TLB 未命中。"

- TLB refill 的页表行走本身要走 L2/L3/DRAM——**页表页也是缓存行的竞争者**：8× 齐射把页表页挤出缓存 → 页走变长
- 且宿主侧多 VM 轮转同一物理核会冲刷 TLB（VMID/ASID 切换）→ guest 的 TLB 未命中率本身上升
- 检验：`perf -e l1d_tlb_refill,l1i_cache_refill`（可加进 percpu 管线，零成本）

### 4. MLP（内存级并行，§6 超标量/多发）

超标量核可维持多个在途 miss（停顿重叠）——排队使在途 miss 串行化 → 实际停顿 > `MPKI×平均时延` 的线性模型。无直接计数器，作为模型残差的兜底解释。

## 四、思维模式（书 §2：先测量后归因）

残差出现时的行动顺序：
1. inst 对比（已在手）——先排除"干得更多"
2. guest_user vs guest_sys 拆分（已在手）——内核路径增长直接可见
3. TLB/i-cache refill 事件（可加）——便宜，先加防患
4. 一致性敏感实验（共享行探针）——书启发的定制检验
5. SMT 并发分析——最后，预期贡献小

## 五、综合结论

书籍视角对残差清单的排序修正（与此前纯工程判断的差异）：

| 候选 | 工程直觉排序 | 书籍视角修正 |
|---|---|---|
| 共享行一致性命中膨胀 | 未列出 | **新增且提权**——我们的多拷贝共享模板页场景恰好命中此机制 |
| SMT sibling 争用 | 中 | **降权**——低 IPC 负载 SMT 惩罚小（书中明确） |
| TLB/页表 | 中 | 维持（页表页被挤出与 MPKI 耦合，部分已隐含在时延里） |
| MLP 退化 | 低 | 维持（兜底） |
| inst 增长 | 高 | 维持（零成本先查） |

**给采集管线的增量建议**（8× 重发前）：percpu perf 加 `l1d_tlb_refill,l1i_cache_refill` 两个事件；可选加"共享行探针"（同一物理页集多进程访问 vs 私有页访问的时延差）以检验一致性膨胀分量。
